# RideWay — пилот

Поездки сотрудников в офис и обратно: 3 машины участников проекта, 3 маршрута, 3–4 места, 100 сом за поездку.
Требования — [PILOT_SPEC.md](PILOT_SPEC.md).

**Состав:** одно приложение ASP.NET Core (.NET 10):
- **Telegram Mini App** (`/app`) — весь интерфейс пассажира (маршруты, запись, разовые поездки, «не еду», оплата, посадка по QR) и водителя (список рейса, отметки, прибытие, отмена);
- **Telegram-бот** — только вход по номеру телефона, кнопка открытия приложения, посадка по QR с камеры и уведомления;
- **веб-админка** (Razor Pages) — маршруты, машины и QR-наклейки, люди, рейсы, оплаты, сводка метрик, журнал;
- **SQLite** — один файл БД, миграции применяются при старте.

## Запуск локально

```bash
dotnet run --project src/GoHome.Web --launch-profile http
```

Админка: http://localhost:5111, пароль в Development — `admin`. В Development создаются демо-маршруты (`SeedDemoData`).

Токен бота от @BotFather (не коммитьте его):

```bash
dotnet user-secrets --project src/GoHome.Web set "Bot:Token" "<токен>"
```

### Mini App локально

Telegram открывает Mini App только по **HTTPS**. Для локальной проверки нужен туннель, например Cloudflare:

```bash
cloudflared tunnel --url http://localhost:5111
```

Полученный адрес `https://….trycloudflare.com` пропишите и перезапустите приложение:

```bash
dotnet user-secrets --project src/GoHome.Web set "App:PublicUrl" "https://….trycloudflare.com"
```

При старте бот сам ставит кнопку «RideWay» в меню чата. Адрес quick-туннеля меняется при каждом запуске — тогда обновите `App:PublicUrl`.

Отладка интерфейса в обычном браузере (только Development): `http://localhost:5111/app/?dev=<telegramId>` — подставляет пользователя с этим Telegram ID без подписи Telegram.

## Места в салоне

- У каждой машины есть **схема мест**: сетка до 8×5 с рулём и пронумерованными сиденьями (по умолчанию — седан «руль, место 1 впереди, ряд 2-3-4»).
  Правят её водитель (приложение → «Водитель» → «Машина») и админ («Машины»). Число мест машины всегда равно числу сидений в схеме.
- **Номера мест закреплены за сиденьями** и не сдвигаются при правке схемы. Нельзя убрать место, на которое записан постоянный пассажир или есть будущая разовая бронь.
- Пассажир при записи на маршрут **выбирает место** на схеме (одно на утро и вечер; можно сменить без перезаписи). Занятые места видны, чужие имена — нет.
  Если мест нет — очередь ожидания; админ даёт место из очереди на странице «Пассажиры».
- На разовую поездку место выбирается на схеме конкретного рейса. Место постоянного пассажира с отметкой «не еду» свободно и доступно для разовой брони;
  если его уже заняли, вернуть «Еду» нельзя.
- Утренний и вечерний пассажиры одного сиденья могут делить его: занятость считается по направлениям.
- **Фото салона** загружает водитель или админ; пассажиры видят его на экране маршрута. Файлы хранятся в `Storage:Path` (в Docker — `/data/uploads`).
  Фото сжимается в приложении до 1600 px; сервер принимает JPEG/PNG/WebP до 6 МБ и проверяет сигнатуру файла.
- Админка: схема салона на странице «Рейсы» показывает, кто на каком месте (постоянный / разово / сел); «Пассажиры» и «Водители» — отдельные разделы.
- Записи, созданные до появления выбора мест, получают схему и места автоматически при первом запуске.

## Карты и остановки

- У каждой остановки есть **место на карте** и необязательный **ориентир** («у входа в ТЦ»). Админка → «Маршруты» → маршрут → блок «Карта и места остановок»:
  выберите остановку в списке и нажмите на карте, метки можно перетаскивать.
- Линия маршрута: по умолчанию прямые между остановками (серый пунктир). Кнопка **«Построить по дорогам»** строит линию по улицам через OSRM
  и показывает длину и время без пробок; изменение остановок или их порядка сбрасывает линию.
- Пассажир видит карту на экране маршрута: нажатие на метку выбирает остановку; под картой «Проложить путь» (Google Maps) и «Открыть в 2ГИС».
  На главном экране есть ссылка «Как добраться до остановки».
- Водитель видит карту рейса: цифры на метках — сколько человек садится/выходит на остановке; у пассажира в списке остановка открывается в картах.
- Карта — Leaflet (лежит в `wwwroot/lib/leaflet`, CDN не нужен) на плитках OpenStreetMap. Плитки и демо-сервер OSRM бесплатны без ключей, но рассчитаны на лёгкую нагрузку:
  для пилота хватает, для рабочей эксплуатации возьмите свой OSRM/провайдера плиток (адрес маршрутизации — `Routing:BaseUrl`).

## Посадка по QR

1. Админка → «Машины» → внизу QR-наклейка для каждой машины. Распечатайте и наклейте в салоне.
2. Пассажир при посадке сканирует QR камерой телефона (откроется бот) или кнопкой «📷 Я в машине» в приложении.
3. Поездка отмечается сама, если пассажир есть в списке рейса и сейчас окно посадки: за 30 минут до его времени посадки и в течение часа после.
4. Водитель видит галочки в своём списке; кнопки ✓/✗ — запасной вариант.
5. Если QR сфотографировали и отмечаются не из машины — «Перевыпустить» под наклейкой, старый код перестанет работать.

## Развёртывание (Docker)

```bash
cp .env.example .env   # задать ADMIN_PASSWORD, BOT_TOKEN, PUBLIC_URL (https)
docker compose up -d --build
```

Порт 8080. БД и ключи cookie — в томе `gohome-data` (`/data`). Бэкап — скопировать `/data/gohome.db`.
Перед контейнером нужен HTTPS (Caddy/nginx или Cloudflare Tunnel): без него Mini App не откроется.

## Первый запуск пилота

1. «Люди» → добавить водителей (имя, телефон, роль «Водитель») и себя («Админ»).
2. «Машины» → 3 машины, число мест, водитель; распечатать QR-наклейки.
3. «Маршруты» → 3 маршрута, остановки по порядку утренней поездки; последняя — офис (её утреннее время = плановое прибытие).
4. Водители и пассажиры открывают бота, делятся номером и дальше работают в приложении. Водитель/админ узнаётся по номеру из п. 1.
5. При посадке пассажиры сканируют QR; водитель по прибытии жмёт «🏁 Прибыли» — из этого считаются оплаты и метрики.
6. В пятницу бот присылает пассажирам сумму к оплате; оплату отмечают в «Оплатах».

## Настройки

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `App:PublicUrl` | — | HTTPS-адрес приложения (для Mini App и ссылки на админку) |
| `Bot:Token` | — | Токен бота; пусто — бот выключен |
| `Bot:Username` | из getMe | Имя бота для QR-ссылок, если бот на этом сервере не запущен |
| `Routing:BaseUrl` | `https://router.project-osrm.org` | Сервис построения линии маршрута по дорогам (OSRM) |
| `Storage:Path` | `uploads` | Папка для фото салонов (в Docker `/data/uploads`) |
| `Pilot:ChangeDeadline` | `21:00` | До какого времени накануне можно отметить «не еду» / записаться / отменить |
| `Pilot:ChargeNoShow` | `false` | Брать ли плату за неявку без предупреждения (неявки считаются в любом случае) |
| `Pilot:BookingDaysAhead` | `5` | На сколько рабочих дней вперёд показывать разовые поездки |
| `Pilot:Holidays` | `[]` | Праздники (`"2026-12-31"`), рейсов нет |

## Устройство

- `Domain/Entities.cs` — сущности. Таблицы «рейс» нет: рейс = (маршрут, дата, направление).
- `Services/TripService` — список на рейс: постоянные − «не еду» + разовые.
- `Services/BookingService` — все операции с местами под одной блокировкой (процесс один — этого достаточно).
- `Services/TripOpsService` — посадка (в том числе по QR), неявка, прибытие, отмена рейса.
- `Services/BillingService` — к оплате = поездки − платежи.
- `Services/MetricsService` — метрики пилота для сводки.
- `App/MiniAppApi.cs` — API Mini App (`/api/app`), авторизация по подписанному Telegram initData (`App/TelegramInitData.cs`).
- `wwwroot/app/index.html` — интерфейс Mini App (без сборки, тема берётся из Telegram).
- `Bot/` — бот: вход по номеру, QR-диплинк, кнопка приложения, плановые уведомления (водителям список в 21:05, пассажирам счёт в пятницу 19:30).
- `INotifier` — канал уведомлений, отделён от логики (сейчас Telegram).
