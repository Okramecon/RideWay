# RideWay — пилот

Поездки сотрудников в офис и обратно: 3 машины участников проекта, 3 маршрута, 3–4 места, 100 сом за поездку.
Требования — [PILOT_SPEC.md](PILOT_SPEC.md).

**Состав:** одно приложение ASP.NET Core (.NET 10):
- **Telegram-бот** — пассажиры (запись на маршрут, разовые поездки, «не еду», сумма к оплате) и водители (список, посадка, прибытие, отмена рейса);
- **веб-админка** (Razor Pages) — маршруты, машины, люди, рейсы, оплаты, сводка метрик, журнал;
- **SQLite** — один файл БД, миграции применяются при старте.

## Запуск локально

```bash
dotnet run --project src/GoHome.Web --launch-profile http
```

Админка: http://localhost:5111, пароль в Development — `admin`. В Development создаются демо-маршруты (`SeedDemoData`).

Чтобы включить бота, создайте бота у @BotFather и задайте токен (не коммитьте его):

```bash
dotnet user-secrets --project src/GoHome.Web set "Bot:Token" "<токен>"
```

Бот работает через long polling — публичный адрес не нужен.

## Тесты

```bash
dotnet test
```

Покрыто: вместимость (в том числе параллельные брони), очередь ожидания, «не еду» и дедлайн 21:00, отмена рейса с уведомлениями, начисления и оплаты.

## Развёртывание (Docker)

```bash
cp .env.example .env   # задать ADMIN_PASSWORD, BOT_TOKEN, PUBLIC_URL
docker compose up -d --build
```

Админка на порту 8080. БД и ключи cookie — в томе `gohome-data` (`/data`). Бэкап — скопировать `/data/gohome.db`.
Для доступа извне поставьте перед контейнером reverse proxy с HTTPS (Caddy/nginx).

## Первый запуск пилота

1. «Люди» → добавить водителей (имя, телефон, роль «Водитель») и себя («Админ»).
2. «Машины» → 3 машины, число мест, водитель.
3. «Маршруты» → 3 маршрута, остановки по порядку утренней поездки; последняя — офис (её утреннее время = плановое прибытие).
4. Водители и пассажиры открывают бота и делятся номером. Водитель/админ узнаётся по номеру из п. 1.
5. Каждый день водитель отмечает в боте «сел / не пришёл» и «прибыли» — из этого считаются оплаты и метрики.
6. В пятницу бот присылает пассажирам сумму к оплате; оплату отмечают в «Оплатах».

## Настройки (`appsettings.json`, раздел `Pilot`)

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `ChangeDeadline` | `21:00` | До какого времени накануне можно отметить «не еду» / записаться / отменить |
| `ChargeNoShow` | `false` | Брать ли плату за неявку без предупреждения (неявки считаются в любом случае) |
| `BookingDaysAhead` | `5` | На сколько рабочих дней вперёд показывать разовые поездки |
| `Holidays` | `[]` | Праздники (`"2026-12-31"`), рейсов нет |

## Устройство

- `Domain/Entities.cs` — сущности. Таблицы «рейс» нет: рейс = (маршрут, дата, направление).
- `Services/TripService` — список на рейс: постоянные − «не еду» + разовые.
- `Services/BookingService` — все операции с местами под одной блокировкой (процесс один — этого достаточно).
- `Services/TripOpsService` — посадка/неявка, прибытие, отмена рейса.
- `Services/BillingService` — к оплате = поездки − платежи.
- `Services/MetricsService` — метрики пилота для сводки.
- `Bot/` — Telegram: обработчик, тексты, плановые уведомления (водителям список в 21:05, пассажирам счёт в пятницу 19:30).
- `INotifier` — канал уведомлений, отделён от логики (сейчас Telegram).
